- **Kaggle version evidence:** The plan does not claim the current adapter already meets the contract. Current `tools/kaggle/cli.py` parses a table-only kernel list, performs an unversioned status check, and returns raw push output (`cli.py:101–116, 371–389`); it has no exact-version assignment/cross-check flow. The plan requires exact positive push-response version, JSON `current_version_number` corroboration, polling only that assigned version, sanitized evidence, and fail-closed behavior for missing/conflicting version evidence (`plan:40–48, 108`). Official CLI documentation supports version-qualified kernel references/status and JSON formatting for `kernels list`; the adapter and deterministic tests remain a necessary pre-submission implementation gate ([Kaggle kernels CLI](https://github.com/Kaggle/kaggle-cli/blob/main/docs/kernels.md), [CLI output formats](https://github.com/Kaggle/kaggle-cli/blob/main/docs/output_format.md)). - **Events/order:** The recovery amendment binds exactly two IDs and reservations; preflight precedes every push; attempt evidence follows terminal resolution and binds preflight/prior attempt; legacy indices 0–12 remain untouched; the new benchmark artifact is linked to its successful attempt, immediately followed by the lock, then separately attested; training is post-lock and pins that lock (`plan:40–54, 77, 82, 89, 104, 108–112`). Missing/ambiguous versions and statuses do not permit a guessed retry. The event schemas and test obligations are sufficiently concrete for implementation.
- **Package immutability:** Both benchmark and training variants are built and hashed before amendment/registration. Each registration pins the exact incumbent/candidate variants and selection rule; after registration no package rebuild/substitution or semantic change is accepted. Post-lock training retries use the exact selected package and frozen bounds (`plan:44, 76–78, 83–84, 90–92, 107, 109`).
- **Leakage/selection:** The benchmark is paired across identical state/model/optimizer/RNG snapshots and frozen inputs, with parity checked before timing. Only runtime/parity/throughput evidence is emitted; benchmark checkpoints and strategic outcomes are not persisted. Candidate training selection requires parity, median paired gain ≥10%, and ≥4/5 pairs individually ≥10%; otherwise the exact incumbent is used (`plan:44, 74–76, 84–85, 109, 113`). This preserves the benchmark's performance-only role.
- **10,000/s miss:** A miss is reported against the unchanged hard G008 threshold and does not cancel the separately authorized bounded training workload. The plan still withholds G008 approval pending the original validation, final-opponent, anti-regression and ONNX/browser gates (`plan:14, 85, 90, 97`).
